Expense Management App Review – Executive
Summary
This  report  analyzes  the  given  expense‐management  wireframes  and  outlines  detailed
recommendations. We map the current workflows (employee submission, manager approval, admin
setup), UI fields and states, and identify edge cases. Key priorities include usability, security, auditability, 
multi-currency  handling,  OCR-based  receipt  capture,  and  accessibility/scalability.  We  compare  leading
systems (Expensify, SAP Concur, Zoho Expense, Ramp, Brex) on features, approval logic, currencies,
OCR, role management, audit logs, and mobile UX
. A feature comparison table is provided. We
then list usability flaws in the wireframes (with severity) and fixes, backed by UX best-practice guidelines
. Revised Mermaid flowcharts depict improved Employee, Manager and Admin processes. We
suggest UI mockup-level changes (with priority), propose a refined data model (ER diagram) with
validation  rules,  and  outline  security/compliance/audit  recommendations.  Implementation  effort  is
estimated for each change. All assertions and designs reference official product documentation and UX
research where available.

Usability Issues in Wireframes
Analysis of the provided wireframe mockups reveals several UX problems:
Unclear Field Labels and Grouping (High): Some input fields lack clear labels or explanations.
For example, currency fields or tax fields are not clearly labeled or placed. Grouping related
fields (amount, currency, category) into a single visual section is advised
. Fix: Ensure every
input has a visible label (not just placeholder text) and group fields logically (e.g. an “Expense
Details” section). Use sufficient spacing or boxes to separate sections
.
Poor Layout and Hierarchy (High): The multi-column layout (desktop + mobile screens) may
confuse users. Nielsen recommends a single-column flow where possible, as multi-column forms
increase cognitive load
. Fix: Redesign the form into a single-column vertical layout on
desktop. Highlight the primary action (“Submit expense”) and clearly separate it from secondary
actions. Use progressive disclosure (e.g. hide advanced fields initially).
Missing Inline Validation and Error States (High): The wireframe lacks indication of validation.
There is no visual feedback if a required field is missing or an entry is invalid (e.g. negative
amount). Fix: Add real-time validation (e.g. error messages on blur for each field, red borders for
invalid input) and a summary of issues on submit failure. Indicate required fields with asterisks
or labels.
Ambiguous Buttons and Labels (Medium): Buttons like “Upload” or “Submit” are not
consistently labeled with their outcomes. It’s unclear if “Upload” saves or submits. Fix: Use clear

No State Indicators or Confirmations (Medium): The mockups do not show what happens
after submission. Users should see confirmation and status. Fix: After submit, display a
confirmation banner (“Expense submitted”), and in the expense history list, show clear states
(Pending, Approved, Rejected). Use colors/icons for status.
Receipt Upload UX (Medium): The receipt upload area is generic. It’s unclear if users can drop
multiple files, preview, or retry a failed upload. Fix: Provide a drag-and-drop area or camera icon.
Show thumbnails of uploaded receipts. Allow re-upload or deletion. Indicate maximum file size/
type.
Currency & Conversion (Medium): The wireframe has an “Amount” and “Conversion” but lacks
context. It’s not clear if the user must enter both or if conversion is automatic. Fix: If foreign
currency is allowed, label fields as “Amount (original currency)” and “Equivalent in [base
currency]”. Auto-calc conversion using real-time rates (as Expensify does
). Otherwise gray
out one field and auto-fill.
Lack of Accessibility Considerations (Medium): No mention of accessibility. Color-coded status
or instructions with only color cues hinder vision-impaired users. Fix: Ensure all text has sufficient
contrast. Associate <label>  tags to inputs, and include descriptive alt text for any icons.
Support keyboard-only navigation and screen readers (ARIA labels for custom widgets).
Responsiveness and Mobile Differences (Low): The mockup does not show mobile-specific
patterns. Complex tables and wide forms may not adapt. Fix: For mobile, collapse fields into one
column, use large touch-friendly buttons, and allow camera capture. Consider a simplified
mobile UX where possible (e.g. scanning receipts by default).
Missing Error/Empty States (Low): The manager’s approval queue should handle “no pending
expenses” gracefully. Fix: If the list is empty, show a friendly message (“No expenses to review”)
rather than a blank screen.
Severity Key: Critical = prevents key task; High = major friction; Medium = noticeable issue; Low = minor
improvement. Where possible, cite NN/g principles
.

Suggested UI Changes (Mockup-Level)
Below are concrete UI refinements, each labeled Must/Should/Could by priority:
Must: Use single-column forms with persistent labels. As NN/g advises, avoid placeholder-only
labels and multi-column layouts
. Fix: Move to a vertical layout; keep all labels outside inputs.
Group related inputs (Amount & Currency, Category & Project, Dates) under headings (e.g.
“Expense Details”)
. 
Must: Add inline validation and clear error messages. For example, after entering a negative
amount or missing field, show an error next to that field. Fix: Implement real-time checks (e.g.
amount >0, date ≠ future, receipt required over threshold). Highlight errors in red with text.
Should: Clarify currency input. Show both original and base currency clearly. Fix: Add a currency
selector next to “Amount”, and auto-calculate the base amount (with a lock icon if auto) or let
user enter an exchange rate. Display “Total in [Base Currency]: ₹X.XX” live. Reference Expensify’s
approach
.
Should: Improve receipt upload area. Fix: Replace generic icon with a drag/drop box or camera
button. Show thumbnail of uploaded image. Allow multiple receipts per expense (if needed). Add
a tooltip “Supported formats: PDF, JPG, PNG. Max 5MB.”
Should: Enhance “Submit” button prominence and state. Fix: Make it a standout color (e.g.
green) and disable it until required fields are valid. Show spinner or “Submitting…” after click.

Could: Provide a progress indicator or breadcrumb for multi-step flows. Fix: If submission spans
pages (e.g. “Details” then “Review” then “Confirm”), show steps. Even for single page, a “X of Y”

Must: Ensure accessibility compliance. Fix: All form fields must have associated <label>  tags.
Use ARIA labels for custom components. Maintain contrast ≥4.5:1 for text. Ensure keyboard
navigation (tab order logical) and screen-reader announcements for dynamic events (e.g.
“Expense submitted”).
Could: Mobile-specific adjustments. Fix: For mobile layouts, collapse inputs into one column,
enlarge touch targets (buttons ≥44px), and use native camera integration to snap receipts. Omit
non-critical fields (e.g. hide non-mandatory categories under “Advanced” toggle) to reduce
clutter.
Should: Add confirmation modals for destructive actions (e.g. delete expense or revoke
submission). Fix: Before deleting an expense or rejecting without reason, prompt user “Are you
sure?”
Must: Label all required fields and use consistent date pickers. Fix: Mark mandatory fields with
“*”. Use a unified date-picker control (with manual input fallback) to prevent format errors.

Proposed Data Model (ER Diagram)
erDiagram
    COMPANY ||--o{ USER : employs
    COMPANY ||--o{ EXPENSE : owns
    USER }|..|{ ROLE : has
    USER ||--|{ EXPENSE : submits
    USER ||--o{ EXPENSE_APPROVAL : approves
    EXPENSE ||--|{ EXPENSE_APPROVAL : "has"
    EXPENSE ||--o{ RECEIPT : attaches
    EXPENSE_APPROVAL }|..|{ APPROVAL_STEP : follows
    APPROVAL_STEP ||--|| APPROVAL_RULE : implements
    EXPENSE ||--o{ APPROVAL_RULE : triggers
    EXPENSE ||--|{ EXPENSE_ITEM : contains
    EXPENSE_ITEM ||--|| CATEGORY : category_type
    EXPENSE ||--o{ CURRENCY : uses
Legend: Users  belong  to  Companies.  Each  User has  a  Role (Admin/Manager/Employee).  A  User
submits many Expenses; each expense is in one Currency (with base currency per company). Receipts
(images) attach to expenses. An Expense may have multiple Expense_Items (if itemized), each linked to
a Category. 
Approvals: Each expense traverses an approval chain. We model this via an Expense_Approval table
(expense_id, approver_id, status, comment, timestamp). Custom Approval_Rules (triggered by amount,
percentage or role) point to required Approval_Steps. A company can define multiple approval rules
(e.g. “50% quorum or CFO approval”).
Validations / Constraints:
- Expense.amount and item.amount ≥ 0, required.
- Expense.date must be ≤ today.
- User.manager_id → User.id (self-referential). Prevent circular reporting.

Security, Compliance, and Audit Recommendations
Role-based  Access  Control  (RBAC): Enforce  strict  permissions.  Only  admins  should  access
settings and define rules; managers only see their team’s expenses. Backend must verify every
action against user’s role. (Principle of least privilege.)
Data Encryption: Store sensitive data securely. Expense entries and attachments (receipts)
should be encrypted at rest. Use HTTPS/TLS for all network communication.
Audit Logging: Log all critical events: expense submission, edits, approvals/rejections, login
attempts, rule changes. Each log entry should include user ID, timestamp, action details. These
logs enable investigation of disputes and support regulatory audits. (Zoho’s audit feature
and Ramp’s audit trail
 illustrate the expectation of full traceability.)
Currency & Compliance: For multi-currency, ensure exchange rates come from a trusted source
(e.g. Open Exchange Rates used by Expensify
). Record the rate used for each transaction to
allow retrospective auditing. For VAT/GST compliance, capture tax/VAT numbers per receipt and
integrate with tax rules (see Brex VAT tracking
).
Receipt  Management: Treat  scanned  receipts  as  financial  records.  Ensure  tamper-evident
handling: once approved, prevent users from altering receipts. Maintain originals for audit (store
checksums).
Mobile App Security: If building a mobile interface, follow OWASP Mobile Top 10: use certificate
pinning, secure storage (avoid plaintext), enforce short session timeouts. 
GDPR/Privacy: If  operating  in  Europe,  allow  users  to  request  data  export/deletion.  Mask
personal data in logs if not needed for audit.
Testing and Compliance: Regularly test with real scenarios and, if needed, seek SOC2/ISO27001
certification for data handling processes.
Implementation & Effort Estimates
We classify each major change as Low/Medium/High effort for engineering:
Form layout rework: Low. Adjust CSS/HTML for single-column, add labels and grouping
containers. 
Input validation (client & server): Medium. Implement front-end checks and back-end field
validation (e.g. numeric checks, required fields).

Currency conversion integration: Medium. Call a currency API (e.g. ExchangeRate API) on-the-
fly or on save. Cache rates. 
Receipt OCR integration: High. Integrate a mobile/web scanning library or service. Expensify
built SmartScan – alternatives include AWS Textract/Google Vision OCR. Ensuring accuracy (14
languages, multi-line items) adds complexity. 
Role/Approval logic: High. Implement configurable multi-step workflows. Requires data model
changes, UI for setting rules (if not present), and dynamic approval routing engine. 
Audit trail logging: Medium. Record all key actions in a logging system or audit table. If using a
framework, enable built-in audit features (like record-versioning plugins). Ensure logs are
immutable. 
Mobile app/UI: High. Designing and coding responsive/mobile layouts or native apps.
Implement camera upload and offline queueing. 
Security hardening: Medium. Set up TLS, input sanitization, RBAC checks in each endpoint.
Possibly use security audits. 
Accessibility fixes: Low. Adjust HTML semantics, ARIA tags, color contrast. 
Bulk-approval feature: Medium. Allow managers/admins to approve multiple reports at once. UI
to select/deselect. (Expensify’s new bulk approvals
.) 
Notification system: Medium. Email/push notifications on status change. 
Automated testing: Medium. Write unit/integration tests for currency, OCR, approvals.
Overall, core improvements (form, validation, audit, roles) are Medium effort. Advanced features (OCR,
mobile apps, dynamic approval engine) are High. Many tasks can be scoped and phased (e.g. launch
minimal viable flow, then add OCR or mobile incrementally).
